# Bounded HIF local scientific type/role verification V1

The owner's direct B4.11 request authorizes exactly two frozen HIF-1α protein
observations listed in bounded_hif_local_identity_scope_v1.json. This document
implements that permission; it is not an independent expert review or signature.
The owner record binds these policy bytes, scope bytes, original request bytes
and actual provenance. No other target, source or experimental revision qualifies.

Affirmative evidence requires the exact frozen source packet, source hashes and
coordinates, original native/Core, B3/B4 and B4.10 revision, exact HIF-1α mention,
source-reported protein/Western-blot readout, and source-specific exposure and
reference context. Frozen captions/Results are individually quoted. Their exact
content, current frozen record and context must all agree. Missing/conflicting
support abstains; similarity, gene aliases and paragraph proximity are insufficient.

The permitted scientific type is existing type protein. The permitted roles are
reported protein measurement target and source-described reduced-oxygen exposure.
The latter is a verified role/context, not a canonical exposure/subject identity.
Verbatim source mention validation clears only this new exact, uncleaned mention;
no historical cleaner status is overwritten, and blocked lineage cannot be cleared.
Existing candidate local-equivalence receives validated protein type, exact raw
surface/lineage and measurement-target role, without aliases or canonical IDs.
It can establish only broad local target correspondence. StructuredSemanticValueV1
and ScientificPropositionSignatureV1 remain unchanged; no subject/object IDs are
filled. Same target does not establish operational/assay equivalence, exact isoform,
external ID, comparison-link direction, causal regulation or experimental equivalence.

Authority dimensions are separate: A source integrity, B protein type, C exposure
role, D measurement role, E local target correspondence, F external canonical ID,
G operational equivalence, H comparator orientation, I scientific machine reuse.
A–E can be established in the bounded scope with evidence; F–I are not granted.
Source reference labels can be verified while formal comparator orientation remains
unresolved. Independent scientific validation and formal promotion stay false.

Use existing IssuerPermission shape with development_provisional environment and
software_provisional_assessor kind. The only permission is
bounded_hif_local_type_role_v1. It is issued by the explicit owner-scoped record,
not by a receipt. No B4.6 machine/provenance scope is enlarged. The software issuer
can issue a source-backed local type/role decision, never materializable relations.

Receipts bind exact evidence assessment, policy/profile/owner hashes, validator
identity and issuance time. Owner and receipt validity are capped at 24 hours.
Current receipt IDs are kept in a separate caller-selected lifecycle checkpoint;
missing current checkpoint, superseded IDs, revoked IDs, unknown issuer, wrong
scope/environment, drifted inputs/validator, future/expired time or insufficient
source evidence blocks verification. The verifier requires separately supplied
trusted owner authorization and current checkpoint, checks actual source again,
and recomputes the expected scientific assessment. Receipt metadata or a correct
receipt hash alone cannot authenticate authority or establish evidence sufficiency.
A caller selects a new immutable lifecycle checkpoint to revoke/supersede a prior
revision; receipt payloads and historical checkpoints are never edited.

ScientificEntityIntegrityGateV1 is unchanged. Submit validated protein-target
state alongside actual unresolved subject/object/exposure identity, endpoint and
other mandatory fields. Do not omit unresolved states or use None/empty legacy
compatibility. Gate rejection is acceptable. L4c remains staging_only; no formal
alignment, conflict qualification, causal hypothesis, Gold or Strict Core follows.

Raw provider cache identity is untouched. Derivations include actual policy,
owner, scope, lifecycle, source and implementation hashes. All evidence remains
AI_PROVISIONAL_NOT_INDEPENDENTLY_VALIDATED with precisely bounded local authority.
